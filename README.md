# 宝塔地图（GM 实时绘制）

一个面向桌游 / TRPG《宝塔》游戏的地图管理网页。GM 可以记录各层房间、门与楼梯的连接、玩家实时位置及行动点，并在后半程手动开启追逐战。网页支持静态地图和通过腾讯云 CloudBase 同步的动态地图。

> 本项目是辅助 GM 记录地图和规则状态的工具，不替代角色卡、外部骰子或 GM 的剧情裁定。所有游戏骰子均由游戏者使用专门的骰子工具投掷，网页不负责掷骰或自动计算伤害。

## 功能概览

- 五层宝塔地图，记录房间类别、坐标、门的连接、楼梯连接和玩家所在位置。
- 可添加、删除玩家，编辑玩家名称、DEX 及每回合行动点数（AP）。
- 玩家独立行动，不强制按 DEX 排序；移动、上下楼、传送等操作会消耗 AP。
- 支持指定楼层和坐标创建房间、随机选择房间类别，以及传送玩家。
- 将普通房间的“设有上行楼梯”和“楼梯间”分开处理。
- GM 可手动启动和控制追逐战，管理白发、束缚、救援、墙中白骨和楼层摧毁状态。
- 支持撤销、移动记录，以及 JSON 地图导入和导出。
- 动态模式下，地图状态通过 CloudBase 同步给只读观看页面。

## 地图模式

首次打开管理网页时，会要求选择地图模式。之后可使用页面右上方的“切换地图模式”重新选择。

### 静态地图

静态模式适合不需要在线实时同步的游戏。地图保存在当前浏览器的本地存储中，GM 可以正常编辑，但更改不会自动推送到其他人的浏览器。可通过截图、共享屏幕或导出 JSON 的方式与 PL 分享。

请注意：浏览器本地存储通常只在同一浏览器配置文件中有效。清理浏览器数据、更换设备或使用不同浏览器之前，建议导出 JSON 备份。

### 动态地图

动态模式适合 GM 与 PL 远程游玩。网页需要托管在服务器上，并连接 CloudBase 文档型数据库。GM 修改地图后，观看页面通过数据库实时监听接收更新，无需 PL 手动刷新。

动态模式需要一定的配置工作，包括 CloudBase 环境、数据库集合、Publishable Key、登录认证和数据库安全规则。网页提供配置入口，但不会替使用者自动创建 CloudBase 资源或配置云端权限。

## 首次部署动态模式

### 1. 发布网页

将 `baota_map.html` 上传到可通过 HTTPS 访问的静态网站托管服务，例如腾讯云 CloudBase 静态网站托管。

### 2. 准备 CloudBase 数据库

在自己的 CloudBase 环境中创建或选择文档型数据库集合。网页默认使用集合名 `baota_maps`，并将地图数据保存在该集合中 ID 为 `main` 的文档内。若使用其他集合，请在网页的 CloudBase 配置区填写实际名称。

代码中的默认环境 ID 仅是开发过程中使用的默认值。开源使用者应填写自己的 CloudBase 环境 ID、地域和 Publishable Key。

### 3. 配置数据库权限

建议为地图文档配置只读访问和 GM 独占写入权限。网页界面提供的规则示例如下，实际使用时请根据自己的 CloudBase 规则配置及账号 UID 替换占位内容：

```json
{
  "read": true,
  "write": "auth.uid == '替换为你的GM用户UID'"
}
```

然后在网页中使用已启用的 CloudBase 登录方式登录 GM 账号，复制当前账号 UID，并将相同 UID 填入“本浏览器的 GM UID”，保存 GM 身份。

**权限提示：** 隐藏编辑按钮或使用只读链接不等于安全控制。数据库安全规则才是写权限的实际边界。上面的 `read: true` 意味着具备数据库访问条件的人都可能读取该地图；若地图内容不适合公开，应进一步限制读取权限。不要把 CloudBase `SecretKey`、服务端密钥或其他私密凭据放入网页。

### 4. 分享玩家观看链接

GM 连接数据库并获得编辑权限后，点击“复制玩家只读链接”，把链接发送给 PL。该链接会包含连接动态地图所需的公开配置参数，并以只读观看模式打开。玩家不应使用 GM 管理页面进行地图编辑。

动态链接中的 Publishable Key 属于客户端公开配置，不应与服务端 SecretKey 混淆。分享前仍应检查数据库安全规则是否正确。

## 基本操作

### 管理玩家

- 点击玩家卡片切换当前操作角色。
- 可以添加玩家或删除当前选中的玩家；至少保留一名玩家。
- 新玩家默认在第一层入口加入游戏，并有默认 AP。
- 编辑玩家信息时可以修改名称、DEX 和每回合 AP。DEX 仅作为信息参考，不决定网页中的强制行动顺序。

### 回合与行动点（AP）

- 每名玩家独立行动。默认每回合 2 AP，可在玩家信息面板中设置为 1–20。
- 每次移动、上下楼、使用传送法宝等操作消耗 1 AP。
- 使用没有专门按钮的其他行动或道具时，GM 可选择“消耗 1 AP（其他道具）”。
- 玩家可以选择“结束该玩家本轮行动”来放弃剩余 AP；其他仍有 AP 的玩家可以继续行动。
- 当所有玩家的 AP 都为 0 时，普通探索阶段自动进入下一轮，并按每名玩家的设定恢复 AP。

网页不代替 GM 记录道具效果、属性检定、生命值或伤害数值。请使用游戏专用骰子，并在角色记录中结算结果。

### 房间与移动

普通移动每次只能前往相邻的一格。地图上只有由门连接的房间才互通；仅在坐标上相邻、但没有门连接的房间不能直接通行。普通房间在首次向未探索方向扩展后会确定出口方向，其他未连接方向视为墙壁。

创建房间时可以选择下列类别：

- 空房间
- 大殿
- 经堂
- 藏宝库
- 廊道
- 珍奇阁
- 居室
- 护法神殿
- 清修室
- 宗祠
- 阴潭
- 杂物间
- 马厩
- 义庄

入口是第一层的特殊起始房间，不属于上述 14 种普通类别。

### 楼梯规则

网页将楼梯相关状态拆为两个独立选项：

- **房间内设有上行楼梯：** 这是一个普通房间，可以沿已有楼梯向上一层移动；这一属性本身不会让房间获得四向扩展能力。
- **本房间是楼梯间：** 楼梯间可以向东、南、西、北四个方向扩展，但不能继续向上爬层。需要继续上楼时，应在当前层找到另一个设有上行楼梯的普通房间。

入口同样可以向四个方向扩展。通过普通上行楼梯到达上一层时，网页会连接或创建上一层的楼梯间。第五层的唯一房间名为“塔顶”，不能继续水平扩展。

### 指定坐标建房与传送

“指定坐标建房 / 传送”面板可指定楼层、X 坐标和 Y 坐标：

- **仅建立房间：** 在该坐标创建房间，不消耗玩家 AP。
- **随机决定房间类别：** 勾选后，由网页随机选择上述房间类别。这只是房间类别的随机选择，不是游戏骰子。
- **传送当前行动玩家：** 将当前选择的玩家传送到目标坐标，消耗 1 AP。
- **目标不存在时自动创建随机房间：** 在目标坐标没有房间时创建一个房间后再传送。追逐战地图已经冻结后，不可在追逐过程中新增房间，只能传送到冻结地图已有的房间。

## 追逐战（第二阶段）

追逐战的触发与对玩家公开是两个不同的步骤，以便 GM 控制剧情揭示时机。

### 触发和开始

1. 当除慕潇以外的玩家首次抵达第五层“塔顶”时，网页记录追逐战触发条件，但不会立即向 PL 显示警报。
2. 当本轮所有玩家都用完 AP 或提前结束自己的行动后，网页将当前探索地图、楼梯连接和各玩家位置冻结为追逐战地图。
3. GM 在追逐战控制面板点击“开启追逐战并通知 PL”。只有这一步执行后，玩家端才显示红色警报“宝塔正在塌陷，请全力逃亡”。

GM 可以在追逐战过程中暂时隐藏或重新显示玩家端提示，也可以手动结束追逐战。

### 玩家逃亡

- 玩家从上塔阶段最终停留的位置开始逃亡；慕潇（白鬼）的本体固定在塔顶。
- 追逐战地图被冻结，不可在白鬼追逐期间新建房间。
- 玩家可沿已经探索并打通的门原路返回，也可以通过已连接的楼梯向下移动；不能继续上楼。
- 本层有多个可下楼楼梯时，GM 可在移动面板选择下楼目标。
- 玩家抵达第一层入口且未被白发束缚时，会被标记为已逃出宝塔。追逐战开始时已在第一层入口的玩家也会按规则标记为逃出。
- 当除慕潇（白鬼）以外的所有玩家都逃出宝塔后，追逐战自动结束。

### 白鬼行动和白发蔓延

每轮所有未逃出的玩家都用完 AP 或结束自己的行动后，轮到白鬼最后行动。GM 使用外部骰子掷 1d3，并将结果手动填写到“白鬼本轮行动点数”中。网页不会代替 GM 掷骰。

每次白鬼行动可选择：

- **白发向前蔓延：** 选择白发下一步要进入的房间。白发只能沿冻结地图中已经存在的门或向下的楼梯连接蔓延，不能向上。白发占据经过的房间，相关房间会在地图上标红。
- **白发攻击玩家：** GM 手动选择目标，网页记录该玩家被白发束缚 3 回合。

完成填写的白鬼行动次数后，点击结束白鬼行动，进入下一追逐轮。网页会提示尚未挣脱的被束缚玩家应受到 2d3 伤害，但不掷骰、不计算伤害，也不维护角色 HP。GM 应使用外部骰子并在角色记录中处理伤害。

### 白发缠身、挣脱与救援

- 被白发束缚的玩家不能移动。
- 每个追逐回合可记录一次力量检定成功或失败。成功时解除束缚；失败时继续保持束缚，并在白鬼回合结算时提醒 GM 处理 2d3 伤害。
- 其他仍在塔内、未被束缚且有 AP 的玩家可以实施救援。GM 先在游戏中确认力量检定成功，再在网页点击救援操作，救援者消耗 1 AP。
- GM 也可以指定场上 NPC 作为救援者。
- 玩家进入已经被白发占据的房间时，会自动进入白发束缚状态。

### 墙中白骨

网页不会自动掷 d4，也不会自动随机选择目标。GM 应在外部掷 d4 后，在“本轮被白骨攻击的玩家”下拉列表中手动选择目标，并确认攻击目标。

之后根据外部敏捷检定记录结果：

- 敏捷成功：记录玩家躲开白骨。
- 敏捷失败：记录玩家进入白骨战斗轮，并限制其移动，直到 GM 点击“白骨战斗结束，解除限制”。

### 楼层摧毁

追逐战控制面板提供第 1–4 层的摧毁检查。网页根据冻结地图中的门连接与白发占据情况，检查入口和通往上一层楼梯之间是否仍有未被白发占据的路径。达到条件后，GM 点击宣告按钮，网页记录并向 PL 显示“第 X 层，摧毁”。该功能用于辅助判断，最终游戏处理仍由 GM 裁定。

## 地图管理与备份

- **撤销上一步操作：** 回退最近一次可撤销的地图状态操作。建议在重要操作前导出备份。
- **导出地图 JSON：** 下载包含地图状态和撤销历史的 JSON 文件，可用于备份或迁移。
- **导入地图 JSON：** 从之前导出的 JSON 恢复地图。导入会替换当前地图状态，请在覆盖现有数据前先导出备份。
- **重置地图：** 清除当前地图、房间和移动记录，并将玩家送回第一层入口。此操作不可轻易恢复，建议先导出 JSON。
- **最近移动记录：** 显示房间探索、玩家移动、行动点消耗及追逐战状态变化等记录。

## PL 观看页面

PL 使用 GM 生成的动态只读链接访问地图。该页面会显示地图楼层、房间、门连接、玩家位置、玩家行动点等共享状态。追逐战开始后，PL 页面显示红色警报、白发占据的房间、玩家束缚状态、已逃出玩家和已宣告摧毁的楼层。

PL 页面是只读视图，地图操作由 GM 完成。静态模式不会自动推送到 PL；若需要实时共享，请使用动态模式并正确配置 CloudBase。

## 故障排查

- **页面没有实时更新：** 确认使用的是动态模式、CloudBase 环境 ID / 地域 / 集合名称正确，GM 已登录并有写权限，数据库安全规则允许 PL 读取。
- **GM 无法编辑：** 检查当前登录 UID 是否与网页登记的 GM UID 一致，并确认数据库规则允许此 UID 写入。
- **玩家链接无法打开地图：** 请让 GM 重新复制只读链接，并确认 URL 中含有 `view=1`、`env`、`region`、`collection` 和 `key` 等动态配置参数。
- **地图或玩家位置异常：** 先导出当前 JSON 备份，再尝试导入最近的有效备份。导入旧版本地图时，网页会对部分旧房间类型和楼梯字段进行兼容迁移，但复杂旧数据仍建议人工核对。
- **动态同步仍有问题：** 检查 CloudBase 网站安全来源设置、数据库安全规则和浏览器控制台错误信息。

## 隐私与安全建议

- 不要将 CloudBase `SecretKey`、服务端密钥、个人账号密码提交到公开仓库。
- Publishable Key 是网页连接配置的一部分，但数据库安全规则仍必须独立限制写入权限。
- 如果不希望地图内容被任意人读取，不要直接使用开放读取规则；请为观看者配置适当的身份验证和读取权限。
- 上传到公开静态托管后，任何被公开的网页代码都可以被访问和检查。不要把秘密剧情、私人数据或服务端凭据作为前端机密保存。
